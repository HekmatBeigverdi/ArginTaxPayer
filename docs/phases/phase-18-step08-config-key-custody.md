## Source findings

- The API unit uses `EnvironmentFile=-/etc/argintaxpayer/api.env`, which is **optional**. The Web unit likewise uses `web.env`. Both units have an explicit activation marker and are currently disabled; a missing env file cannot be mistaken for ready config.
- The API has default operational opt-in OFF. The service unit disables Ghasedak live sending and legacy Sandbox dispatch. The Web unit disables Production UI and identity UI.
- `appsettings.Production.json` contains only the deployment label; it is **not** a secret store or sufficient production configuration.
- Step07 dedicated PostgreSQL uses `argintaxpayer_prod` through TLS VerifyFull with separate migrator/app passwords. The Step07 operator-private credentials and dedicated CA must never be printed, committed or distributed.
- Audited `IdentityMfaCrypto`: `Identity__MfaEncryptionKey` must decode as exactly 32 bytes of base64, AES-256-GCM. Audited `DatabaseKeyProtectionProvider`: `SigningKeyProtection__DatabaseMasterKey` must be a DIFFERENT 32-byte base64 AES-256-GCM key, with `SigningKeyProtection__Enabled=true` and `SigningKeyProtection__Provider=Database`. Both persist in root-only `api.env`; replacing either after encrypting data loses recoverability.
- Audited `IdentitySessionService`: random opaque access and refresh tokens; SHA-256 token digests, revocation and expiration in PostgreSQL. It is **not JWT-based**. Browser BFF cookie security remains Step11 validation.
- Neither systemd environment nor appsettings may configure a single global tax authority target for all fiscal memories. Provider credentials and fiscal RSA private keys are **not** generated by Step08.
