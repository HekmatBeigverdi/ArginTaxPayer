# ثبت کاربر توسط مدیر و تشخیص حساب ثبت‌نام‌نشده

## هدف

کاربرانی که با حساب/شماره ثبت‌نشده برای ورود رمزعبور تلاش می‌کنند باید پیام روشن دریافت کنند و به ثبت‌نام هدایت شوند. مدیر سطح ۱ و سطح ۲ نیز باید بتوانند از فهرست کاربران، حساب مشتری را با اطلاعات هویتی و نشانی ایجاد کنند.

## رویکرد انتخاب‌شده

از مسیرهای موجود Identity و BFF استفاده می‌شود: API ایجاد مشتری فیلدهای پروفایل را در همان تراکنش ذخیره می‌کند، UI یک مودال هم‌سبک پنل فعلی ارائه می‌دهد، و API ورود فقط در صورت نبودن حساب پاسخ مشخص `account_not_registered` می‌دهد. مسیر جداگانه‌ای برای ثبت‌نام ساخته نمی‌شود تا اعتبارسنجی و مجوزهای موجود دوباره‌کاری نشوند.

## محدوده و محدودیت‌ها

- فقط مدیر دارای نشست معتبر و MFA فعال با نقش سطح ۱ یا ۲ مجاز به ایجاد مشتری است.
- فیلدهای موبایل، نام، نام خانوادگی و نشانی الزامی هستند؛ نام شرکت/مؤسسه اختیاری است.
- فرم مدیر رمزعبور را دو بار دریافت و تطبیق می‌دهد؛ ورود کاربر می‌تواند با همین رمز یا مسیر OTP موبایل انجام شود.
- ورود با رمز برای شناسه‌ای که حساب ندارد با خطای مشخص به تب ثبت‌نام هدایت می‌شود؛ خطای رمز اشتباه برای حساب موجود عمومی باقی می‌ماند.
- ثبت پروفایل، مالکیت تجاری و حساب هویتی در یک تراکنش انجام می‌شود.

## اجزای تغییر

1. سرویس provisioning و مدل درخواست API: اعتبارسنجی پروفایل، تولید رمز موقت امن و ایجاد `SoftwareUserProfile`.
2. endpoint ورود: تفکیک نبود حساب از رمز اشتباه.
3. جریان Identity در وب: پیام فارسی و انتقال خودکار به ثبت‌نام.
4. فهرست کاربران: مودال ایجاد کاربر، ارسال به API، نمایش خطا/موفقیت و بازخوانی فهرست.
5. تست‌های رگرسیون API، سرویس و UI.

## خارج از محدوده

تغییر نقش‌های مدیریتی، تغییر مدل OTP، تغییر پایگاه‌داده‌ی تولید یا ایجاد branch جدید.
